Windows Credential Exposure Auditor

The Mimikatz playbook, run as a defensive checklist.

Windows 10/11 · amd64 & arm64 Go 1.26.9+ MIT v2.0.2 cosign keyless signature not Authenticode-signed

OBLITERATUS answers one question — would Mimikatz work against this host? — and answers it with evidence: registry state, token privileges, service configuration and browser store exposure, each mapped to the exact Mimikatz module and MITRE ATT&CK technique it corresponds to.

It ships as a single binary with two modes. The headless audit is safe to run in CI and exits non-zero when a CRITICAL or HIGH control is failing. The dashboard is a local console on 127.0.0.1 with a per-run 256-bit token.

Every offensive capability is compiled in but locked. A locked route answers 403 and names the flag that would unlock it, until the operator passes that flag explicitly. Unlocking prints a [!] ... UNLOCKED banner at startup — the effect is never silent. The full route-by-route gate is in Capabilities.

Verify before you run

  1. Integrity. 
    sha256sum -c checksums.txt
# PowerShell: Get-FileHash -Algorithm SHA256 .\obliteratus_2.0.2_windows_amd64.zip
  2. Provenance. The checksum file is signed keyless with cosign, bound to the workflow run and logged in the Sigstore transparency log. Pin the identity — a bare Verified OK only says someone signed it: 
    cosign verify-blob \
  --certificate checksums.txt.pem \
  --signature   checksums.txt.sig \
  --certificate-identity-regexp "^https://github.com/DevCop95/pullgoscript/" \
  --certificate-oidc-issuer "https://token.actions.githubusercontent.com" \
  checksums.txt
  3. Dependencies. An SPDX SBOM ships per archive: 
    syft convert obliteratus_2.0.2_windows_amd64.sbom.json -o table
Windows will still complain, and that is not a build failure. The .exe files are not Authenticode-signed: Get-AuthenticodeSignature reports NotSigned, SmartScreen shows "Windows protected your PC", and Defender may quarantine on sight of the injection or credential-collection strings. A trusted Authenticode signature needs an EV certificate or an Azure Trusted Signing account — a paid, identity-verified credential this repository cannot hold. Until one exists, the cosign signature is the honest guarantee: this binary came from this repository's release workflow, even though Windows will not validate it natively. Details and the operator/local signing path are in Verify.

Build from source

git clone https://github.com/DevCop95/pullgoscript
cd pullgoscript
go build -o bin\obliteratus.exe .\cmd\obliteratus

Prefer this to the archives if you want to read the code you are about to run. The toolchain floor is Go 1.26.9 — the standard library ships inside the binary, so an old toolchain is a vulnerable dependency.

OBLITERATUS is for authorized security assessment, research and education on systems you own or are contracted to test. The credential-collection, persistence, evasion, lateral-movement and injection modules are deliberately locked; unlocking them is an explicit acknowledgement that your engagement permits their use.
