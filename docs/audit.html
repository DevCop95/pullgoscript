The attack-surface audit

Twelve controls, each one a condition Mimikatz depends on, each carrying a stable ID, a severity, the evidence behind the verdict, a remediation and the exact module it corresponds to. This is the part that runs without any flag — it is read-only and it is the reason the tool exists. 

obliteratus.exe --audit          # human-readable, exit 1 when a CRITICAL/HIGH control fails
obliteratus.exe --audit --json   # machine-readable
obliteratus.exe --audit --csv    # spreadsheet
Checks degrade to unknown, never to a false pass. If a privilege or an asset is missing, the control reports that it could not see, because an audit that guesses is worse than one that admits a gap.

Exit-code contract

Worst severity foundExit codeMeaning for a pipeline
CRITICAL or HIGH failing1Gate the merge / fail the hardening review
MEDIUM, LOW, INFO only0Report, do not fail
Expect exit 1 on a healthy workstation, and read the report before you call it a false alarm. On a fully patched, fully elevated Windows 11 host the live report shows MK-SEDEBUG failing as HIGH: the token carries SeDebugPrivilege but has not enabled it, and a high-integrity admin token can enable it whenever it wants — which is precisely the point the control is making. The contract is about the worst severity, so that one HIGH is what makes a scripted run exit non-zero.

Report shape

Findings carry id, title, severity, status, evidence, remediation, technique and module, alongside tool, version, hostname, generated_at, elevated, modules and a summary count per severity. Stable IDs mean you can diff two runs across a remediation window and see exactly which control moved.

Adding a check is one function plus one line in RunChecks — see CONTRIBUTING.md. The audit package never imports server; progress is reported through an Emitter callback so the checks stay unit-testable.
